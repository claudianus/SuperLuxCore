# Spectral Rendering — hero-wavelength spectral transport

Status: implemented (CPU + GPU). True per-wavelength sampling instead of a
fixed RGB triple, enabling physically-correct dispersion.

## What and why

Ordinary renderers carry one RGB triple per path, which cannot reproduce
wavelength-dependent effects (prism dispersion, thin-film interference, real
material spectra). Hero-wavelength sampling carries a small set of wavelengths
anchored at a randomly sampled **hero wavelength**; each path evaluates the
scene's spectral response at its wavelengths and the result is projected back
to RGB through colour-matching functions. LuxCore samples 3 wavelengths per
path (hero + 2 rotated).

## References

- Wilkie, Nawaz, Droske, Weidlich, Hanika. **Hero Wavelength Spectral
  Sampling.** Computer Graphics Forum (EGSR) 33(4), 2014. (The hero-λ method.)
- Radziszewski, Boryczko, Sun. **An Improved Technique for Full Spectral
  Rendering.** Journal of WSCG 2009. (Companion-wavelength idea.)
- CIE 1931 colour-matching functions — used to integrate SPD -> XYZ -> RGB.

## RGB -> SPD upsampling model (`path.spectral.upsampling`)

Leaf RGB triplets (constant colours, image-map texels, light colours) are
upsampled to spectral bins by a selectable model:

| Value | Model |
|---|---|
| `smits` (default) | Smits-99-style white + secondary + primary basis decomposition (`rgbE_32.h` reflectance / `rgbD65_32.h` illuminant tables), luminance-renormalized per draw. Existing behaviour, zero regression. |
| `jh2019` | Jakob–Hanika 2019 sigmoid basis: `SPD(λ) = sigmoid(c0·λ² + c1·λ + c2)` with the 3 coefficients fetched from a dominant-channel trilinear 32³ table (`jh2019_32.h`). The sigmoid keeps every bin in [0,1] — energy conservation for reflectance by construction (the Smits bases can exceed 1 after luminance renorm). |

Example: `path.spectral.enable = 1` + `path.spectral.upsampling = jh2019`.
The bare `spectral.upsampling` name is accepted as an alias (it takes
precedence when both are set); any other value is rejected with an error.

### Provenance

- Paper: W. Jakob, J. Hanika, *"A Low-Dimensional Function Space for
  Efficient Spectral Upsampling"*, EGSR 2019.
- Reference implementation / optimizer:
  https://github.com/mitsuba-renderer/rgb2spec, BSD-3-Clause,
  (c) 2020 Wenzel Jakob, commit `721145dedf2491851bd46ab8fd165955cb38ddaf`.
- The embedded table was generated by that optimizer at resolution 32
  (294,912 coefficient floats, ~1.1 MB) for the LuxCore gamut —
  `ColorSystem::DefaultColorSystem` SMPTE primaries + white point under
  the flat CIE E illuminant (matching the existing `rgbE` basis
  convention and making the table exact for emission colours too).
  Regeneration recipe: `dev-tools/gen_jh2019_table.py` +
  `dev-tools/rgb2spec_luxcore_gamut.patch`. Resolution 32 is the shipped
  size/quality tradeoff (the rgb2spec default 64³ is ~9 MB).

### Implementation notes / limitations

- CPU: `Spectral::Reflectance`/`Emission` dispatch on the model
  (`src/luxrays/core/color/spectral.cpp`, `UpsampleJH2019`); GPU: the
  host uploads the table as a read-only `__global` buffer whose pointer
  doubles as the model switch (`spectral_funcs.cl`, `Spectral_Upsample`).
  The 1.1 MB table exceeds typical `__constant` limits, hence a global
  buffer (allowed trade-off per design review).
- `jh2019` applies to both reflectance and emission leaf colours (the
  table's illuminant E reproduces the input RGB exactly in both cases).
- Per-bin values stay in [0,1] for in-gamut RGB; out-of-gamut inputs
  (>1 or negative channels) are scaled to unit max before the [0,1]³
  fetch so bins scale the same way the RGB does.
- No per-draw luminance renormalization under jh2019 (renormalizing
  could push a reflectance bin above 1); the 3-bin hero-λ estimator
  carries the usual per-draw variance, which averages out over samples.
- The model flag is process-global on the CPU side (same pattern as
  `Spectral::SetEnabled`); concurrent engines with different settings
  are not supported.
