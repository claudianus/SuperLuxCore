# Texture-driven vector Mapping

Version 2.11.16 adds `vectormapping`, a data-vector texture with `vector`, `location`, `rotation`, `scale` texture inputs and numeric `mode` 0–3 (Point, Texture, Vector, Normal). It preserves Blender/Cycles Euler XYZ order, inverse Texture transforms, per-component safe division at zero scale, and normalized Normal outputs. Vector and Normal modes ignore translation. Inputs and outputs remain coordinate data under spectral transport.

CPU and GPU evaluate the transform directly. Expanding linked rotations through adapter arithmetic textures produced over one million GPU evaluation operations and a conservative evaluation-stack allocation exceeding 100 GiB in the test fixture. That experiment was not committed or released. A direct operation avoids that expansion without changing sample count, quality, integrator or the user's graph. Texture enum entries are appended consistently in host and device copies. The shared payload uses portable `unsigned int` fields; GPU input evaluation has a balanced raw spectral scope. Generic height bump evaluation remains available.

Blender 5.2.1, a full synchronized native/package 2.11.16 profile, and 1280 × 720 renders validate each mode with static TRS, linked spatial TRS, an unlinked constant vector, and zero scale. CPU and actual Metal passed 16 RGB conditions each with maximum mean absolute error below 0.000094. Linked TRS in all four modes also passed CPU and Metal default spectral transport, with maximum mean absolute errors 0.009018 and 0.009938 at 16 samples. All four comparison sheets were inspected for gradient, direction, inverse-transform and normalization meaning.

Source Blender semantics were checked in `intern/cycles/kernel/svm/mapping_util.h`. Evidence lives in the workspace's `test-scenes/validation-2026-10-09/cycles-scene-goal-phase9/`. The adapter harness asserts native and distribution versions match. This does not establish every image/procedural consumer, animated coordinate, instance transform or undeformed ORCO contract. Adapter paths that convert Mapping into legacy image mapping properties remain separately tracked.
